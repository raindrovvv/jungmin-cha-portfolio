1. 문제 정의

1.1 초기 상황

벽이나 문이 시각적으로는 공간을 분리하지만, 소리는 장애물을 무시하고 그대로 들렸다.

플레이어가 방에 있어도 벽 너머 몬스터의 소리가 바로 옆에서 들리는 것처럼 재생되어 공간감이 없었다.

1.2 요구사항

  • 벽/문 뒤의 소리는 작아지고 먹먹하게 들려야 함
  • 몬스터, 함정, 다른 플레이어 모두에 적용
  • 성능에 큰 영향을 주지 않아야 함
  • 디버깅이 가능해야 함

2. 해결 과정

2.1 [1단계] 오클루전 기본 활성화

기존 코드에서는 성능 최적화를 위해 오클루전 체크가 비활성화되어 있었다.

// 기존 코드 (비활성 상태)

if (IsValid(AkComponent))

{

AkComponent->OcclusionRefreshInterval = 0.0f; // 오클루전 꺼짐

}

이를 활성화하여 Wwise가 주기적으로 장애물을 체크하도록 변경했다.

// 수정된 코드 (GS_Monster.cpp, GS_TrapBase.cpp, GS_Player.cpp)

if (IsValid(AkComponent))

{

// 0.2초마다 오클루전 상태 체크

AkComponent->OcclusionRefreshInterval = 0.2f;

}

2.2 [2단계] 자기 자신 차폐 방지

로컬 플레이어의 경우, 본인 캐릭터의 메시가 카메라를 가려서 본인의 소리가 갑자기 작아지는 현상이 발생할 수 있다.

이를 방지하기 위해 로컬 플레이어는 오클루전 기능을 비활성화했다.

// GS_Player.cpp - BeginPlay

void AGS_Player::BeginPlay()

{

Super::BeginPlay();

if (IsLocallyControlled())

{

// 로컬 플레이어: 자기 자신의 오클루전 비활성화

if (AkComponent)

{

AkComponent->OcclusionRefreshInterval = 0.0f;

}

}

else

{

// 리모트 플레이어: 오클루전 활성화

if (AkComponent)

{

AkComponent->OcclusionRefreshInterval = 0.2f;

}

}

}

2.3 [3단계] 카메라 오디오 리스너 충돌 해결

각 시커 캐릭터에 CameraAudioListenerComponent가 달려있어서,

다른 플레이어의 리스너도 동시에 활성화되는 문제가 발견되었다.

// GS_Player.cpp - 리모트 플레이어의 리스너 비활성화

if (!IsLocallyControlled())

{

// 다른 플레이어의 오디오 리스너 완전 비활성화

if (CameraAudioListenerComponent)

{

CameraAudioListenerComponent->Stop();

CameraAudioListenerComponent->Deactivate();

CameraAudioListenerComponent->UnregisterComponent();

}

}

2.4 [4단계] Wwise 프로젝트 설정

언리얼에서 오클루전 값(0~1)을 보내면, Wwise가 “얼마나 소리를 줄일지” 결정한다.

이를 위해 Wwise Authoring Tool에서 다음을 설정했다.

경로:Project → Project Settings → Environmental Curves 탭

설정 항목권장값설명Occlusion Volume-15dB ~ -20dB완전 차단 시 볼륨 감쇠량Occlusion LPF30 ~ 50고음 차단으로 먹먹한 효과

주의: Volume 끝점이 -200dB로 되어 있으면 소리가 완전히 사라지므로, -15dB ~ -20dB 정도로 조절해야 벽 뒤에서도 어느 정도 소리가 들린다.

2.5 [5단계] 개별 사운드 설정

각 사운드의 Positioning 탭에서Diffraction and Transmission체크박스를 활성화해야

벽을 통과하는 소리와 회절 효과가 계산된다.

2.6 [6단계] 디버그 시스템 구축

오클루전이 제대로 작동하는지 확인하기 위해 디버그 라인 시스템을 구축했다.

// GS_AudioComponentBase.cpp - 콘솔 변수 정의

static TAutoConsoleVariable CVarShowOcclusionRay(

TEXT("GS.Audio.ShowOcclusionRay"),

0,

TEXT("Show audio occlusion debug rays (0=Off, 1=On)"),

ECVF_Cheat

);

// 디버그 라인 출력 함수

void UGS_AudioComponentBase::DrawOcclusionDebug(

UWorld* World,

const FVector& SoundLocation,

const FVector& ListenerLocation,

bool bIsOccluded)

{

if (CVarShowOcclusionRay.GetValueOnGameThread() == 0) return;

FColor LineColor = bIsOccluded ? FColor::Red : FColor::Green;

DrawDebugLine(

World,

SoundLocation,

ListenerLocation,

LineColor,

false, // 영구 표시 아님

1.0f, // 1초간 유지 (깜빡임 방지)

0,

2.0f // 선 두께

);

}

콘솔 명령어:

  • 활성화: GS.Audio.ShowOcclusionRay 1
  • 비활성화: GS.Audio.ShowOcclusionRay 0

디버그 라인 색상:

  • 초록색: 장애물 없음 (소리 정상)
  • 빨간색: 장애물 있음 (오클루전 적용 중)

3. 벽/문 콜리전 요구사항

Wwise는 소리 위치와 리스너(카메라) 사이에 Line Trace를 수행하여 장애물을 감지한다.

이때Visibility 채널을 사용하므로, 벽과 문의 콜리전 설정이 중요하다.

설정 항목필요 조건Collision PresetBlockAll 또는 커스텀Visibility 채널Block으로 설정

4. 최종 결과

효과

  • 벽 뒤의 소리가 자연스럽게 감쇠됨
  • 먹먹한 효과로 공간감 향상
  • 디버그 라인으로 실시간 확인 가능
  • 성능 영향 최소화 (0.2초 주기 체크)

5. 향후 참고사항

Wwise 설정 체크리스트

  • Project Settings → Occlusion Volume 커브 설정 (-15dB ~ -20dB)
  • Project Settings → Occlusion LPF 커브 설정 (30 ~ 50)
  • 개별 사운드 →Diffraction and Transmission체크
  • Actor-Mixer 단계에서 설정하면 하위 사운드가 상속받음

언리얼 설정 체크리스트

  • 벽/문 메시의 Visibility 채널이 Block인지 확인

디버깅 방법

  • 콘솔에서 GS.Audio.ShowOcclusionRay 1 입력
  • 초록선: 장애물 없음 / 빨간선: 차단됨
  • Wwise Profiler에서 실시간 오클루전 값 모니터링 가능
