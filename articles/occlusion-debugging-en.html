This document records the implementation and troubleshooting process of the Wwise Audio Occlusion system in the [GAS] project. It addresses the issue of sound passing through walls and doors despite visual barriers, maximizing spatial awareness while preserving runtime performance.

1. Problem Definition

1.1 Initial Situation

Although walls and doors visually separated spaces, sounds ignored these obstacles and played normally. Even when a player was inside a room, sounds from monsters behind walls played as if they were right next to the player, providing no sense of space.

Figure 1: Sounds failed to be blocked because obstacle checks were disabled even when spaces were divided.

1.2 Requirements

  • Sounds behind walls/doors must be muffled and attenuated.
  • Applies to monsters, traps, and other players.
  • Must not significantly impact runtime performance.
  • Must support visual debugging.

2. Implementation Steps

2.1 [Step 1] Enabling Basic Occlusion Check

In the original codebase, occlusion checking was disabled for performance optimization. 

// Original code (disabled state)
if (IsValid(AkComponent))
{
    AkComponent->OcclusionRefreshInterval = 0.0f; // Occlusion turned off
}

I enabled this so that Wwise periodically performs raycasts to check for obstacles. 

// Modified code (GS_Monster.cpp, GS_TrapBase.cpp, GS_Player.cpp)
if (IsValid(AkComponent))
{
    // Check occlusion state every 0.2 seconds (compromise between performance and responsiveness)
    AkComponent->OcclusionRefreshInterval = 0.2f;
}

2.2 [Step 2] Preventing Self-Occlusion

For the local player, the character's own mesh can block the camera (audio listener), causing the character's own sounds (like footsteps) to drop in volume suddenly. To prevent this self-occlusion, I disabled occlusion calculations for the locally controlled player. 

// GS_Player.cpp - BeginPlay
void AGS_Player::BeginPlay()
{
    Super::BeginPlay();
    
    if (IsLocallyControlled())
    {
        // Local Player: Disable self-occlusion
        if (AkComponent)
        {
            AkComponent->OcclusionRefreshInterval = 0.0f;
        }
    }
    else
    {
        // Remote Players: Enable occlusion check for other players
        if (AkComponent)
        {
            AkComponent->OcclusionRefreshInterval = 0.2f;
        }
    }
}

2.3 [Step 3] Resolving Camera Audio Listener Conflicts

In a multiplayer environment, each Seeker character possessed a CameraAudioListenerComponent. This caused listener components on remote characters to activate simultaneously, breaking audio positioning. I resolved this by explicitly stopping and unregistering listener components on remote characters. 

// GS_Player.cpp - Disabling listener on remote players
if (!IsLocallyControlled())
{
    // Completely deactivate and unregister remote player's audio listener
    if (CameraAudioListenerComponent)
    {
        CameraAudioListenerComponent->Stop();
        CameraAudioListenerComponent->Deactivate();
        CameraAudioListenerComponent->UnregisterComponent();
    }
}
Figure 2: Deactivating listener components on remote players leaves only the local player's listener active.

2.4 [Step 4] Wwise Project Configuration

When Unreal Engine sends the calculated occlusion value (0 to 1), Wwise decides "how much to attenuate volume and apply filters". In Wwise Authoring Tool, I set the Environmental Curves tab as follows:

Setting Item Recommended Value Description
Occlusion Volume -15dB to -20dB Volume attenuation when fully occluded (behind obstacles)
Occlusion LPF 30 to 50 Low-pass Filter strength to cut high frequencies for a muffled effect
Warning: If the end point of the Volume curve is set to Wwise's default of -200dB (complete silence), sounds will disappear entirely. Setting it to -15dB to -20dB ensures players can still hear muffled monster sounds through walls and doors to track their locations.
Figure 3: Curve mapping of Occlusion Volume and LPF relationships in Wwise Environmental Curves.

2.5 [Step 5] Individual Sound Settings

For the occlusion settings to take effect on sound sources, the Diffraction and Transmission checkbox in each sound's Positioning tab must be enabled to calculate wall penetration and diffraction.

Figure 4: Enabling Diffraction and Transmission in the Positioning tab of a Wwise sound asset.

2.6 [Step 6] Implementing a Debugging System

To visually verify that occlusion check lines are cast at correct coordinate points at runtime, I implemented a debug line system. 

// GS_AudioComponentBase.cpp - Declaring console variable
static TAutoConsoleVariable<int32> CVarShowOcclusionRay(
    TEXT("GS.Audio.ShowOcclusionRay"),
    0,
    TEXT("Show audio occlusion debug rays (0=Off, 1=On)"),
    ECVF_Cheat
);

// Debug line drawing function
void UGS_AudioComponentBase::DrawOcclusionDebug(
    UWorld* World, 
    const FVector& SoundLocation, 
    const FVector& ListenerLocation, 
    bool bIsOccluded)
{
    if (CVarShowOcclusionRay.GetValueOnGameThread() == 0) return;
    
    FColor LineColor = bIsOccluded ? FColor::Red : FColor::Green;
    
    DrawDebugLine(
        World,
        SoundLocation,
        ListenerLocation,
        LineColor,
        false,      // Persistent
        1.0f,       // Life time (1 second)
        0,
        2.0f        // Line thickness
    );
}
  • Console Commands:
    • Enable: GS.Audio.ShowOcclusionRay 1
    • Disable: GS.Audio.ShowOcclusionRay 0
  • Debug Line Colors:
    • Green: No obstacles (sounds playing normally)
    • Red: Obstacle detected (Wwise occlusion filter applied)
Figure 5: Red debug rays indicating blocked paths in actual gameplay.

3. Wall/Door Collision Requirements

Wwise performs Line Traces between the sound source and listener (camera). Since it uses the Visibility channel, correct collision presets on walls and doors are mandatory.

Setting Item Required Condition
Collision Preset BlockAll or Custom Preset
Visibility Channel Block (must be set to block raycasts)
Figure 6: Blocking the Visibility channel in static mesh collision settings.

4. Final Results

Class Name Occlusion Setup Notes
AGS_Monster Enabled (0.2s check) Applies occlusion to monster footsteps, attack calls, etc.
AGS_TrapBase Enabled (0.2s check) Saw blades, active traps, mechanism sounds.
AGS_Player (Remote) Enabled (0.2s check) Applies occlusion to other player actions and footsteps.
AGS_Player (Local) Disabled Prevents volume dropping errors caused by local camera meshes.
AGS_Door Enabled (0.2s check) Applies occlusion based on opened/closed door states.

Key Benefits

  • Sounds behind walls attenuate smoothly and realistically.
  • LPF muffling enhances spatial awareness, allowing players to read threats intuitively.
  • Debug lines allow real-time validation during testing and QA.
  • Optimized check intervals (0.2 seconds) minimize CPU overhead.

5. Checklists & Debugging

  • Wwise Checklist:
    • Verify Project Settings → Environmental Curves has volume attenuation between -15dB and -20dB to prevent total mute.
    • Set Project Settings → Environmental Curves LPF value (30 to 50).
    • Ensure Diffraction/Transmission is checked at the Actor-Mixer level so child containers inherit the settings.
  • Unreal Checklist:
    • Double-check if Visibility collision on static mesh assets (like doors and walls) is set to Block.
  • Debugging Methods:
    • Execute GS.Audio.ShowOcclusionRay 1 in console to see trace color feedbacks (Green: No obstacles / Red: Blocked).
    • Run Wwise Profiler to trace occlusion values and verify there are no voice drops.
