이 문서는 [GAS] 프로젝트에서 Wwise 오디오 오클루전(Occlusion) 시스템을 구축하고 트러블슈팅한 과정의 기록입니다. 벽이나 문이 시각적으로는 공간을 분리하지만 소리가 무시하고 들리는 현상을 해결하고, 성능을 유지하면서 공간감을 극대화했습니다.

1. 문제 정의

1.1 초기 상황

벽이나 문이 시각적으로는 공간을 분리하지만, 소리는 장애물을 무시하고 그대로 들렸습니다. 플레이어가 방에 있어도 벽 너머 몬스터의 소리가 바로 옆에서 들리는 것처럼 재생되어 공간감이 전혀 없었습니다.

그림 1: 공간 분리 상태에서도 장애물 체크가 이루어지지 않아 소리가 차단되지 않는 초기 상태

1.2 요구사항

  • 벽/문 뒤의 소리는 작아지고 먹먹하게 들려야 함
  • 몬스터, 함정, 다른 플레이어 모두에 적용
  • 성능에 큰 영향을 주지 않아야 함
  • 디버깅이 가능해야 함

2. 해결 과정

2.1 [1단계] 오클루전 기본 활성화

기존 코드에서는 성능 최적화를 위해 오클루전 체크가 비활성화되어 있었습니다. 

// 기존 코드 (비활성 상태)
if (IsValid(AkComponent))
{
    AkComponent->OcclusionRefreshInterval = 0.0f; // 오클루전 꺼짐
}

이를 활성화하여 Wwise가 주기적으로 장애물을 체크하도록 변경했습니다. 

// 수정된 코드 (GS_Monster.cpp, GS_TrapBase.cpp, GS_Player.cpp)
if (IsValid(AkComponent))
{
    // 0.2초마다 오클루전 상태 체크 (성능과 반응성의 절충점)
    AkComponent->OcclusionRefreshInterval = 0.2f;
}

2.2 [2단계] 자기 자신 차폐 방지

로컬 플레이어의 경우, 본인 캐릭터의 메시가 카메라(리스너)를 가려서 본인이 내는 소리(발소리 등)가 갑자기 작아지는 자가 차폐(Self-Occlusion) 현상이 발생할 수 있습니다. 이를 방지하기 위해 로컬 플레이어 본인 캐릭터에 대해서는 오클루전 기능을 비활성화했습니다. 

// GS_Player.cpp - BeginPlay
void AGS_Player::BeginPlay()
{
    Super::BeginPlay();
    
    if (IsLocallyControlled())
    {
        // 로컬 플레이어: 자기 자신의 오클루전 비활성화
        if (AkComponent)
        {
            AkComponent->OcclusionRefreshInterval = 0.0f;
        }
    }
    else
    {
        // 리모트 플레이어: 다른 플레이어 소리는 오클루전 활성화
        if (AkComponent)
        {
            AkComponent->OcclusionRefreshInterval = 0.2f;
        }
    }
}

2.3 [3단계] 카메라 오디오 리스너 충돌 해결

멀티플레이어 환경에서 각 시커(Seeker) 캐릭터에 CameraAudioListenerComponent가 달려있어, 원격 플레이어의 리스너가 중복 활성화되어 오디오 포지셔닝에 오류가 생기는 문제가 있었습니다. 로컬로 제어되지 않는 원격 캐릭터의 오디오 리스너 컴포넌트를 명시적으로 정지 및 등록 해제해 문제를 해결했습니다. 

// GS_Player.cpp - 리모트 플레이어의 리스너 비활성화
if (!IsLocallyControlled())
{
    // 다른 플레이어의 오디오 리스너 완전 비활성화
    if (CameraAudioListenerComponent)
    {
        CameraAudioListenerComponent->Stop();
        CameraAudioListenerComponent->Deactivate();
        CameraAudioListenerComponent->UnregisterComponent();
    }
}
그림 2: 리모트 플레이어의 리스너 컴포넌트 해제 후 1인칭 리스너 포커스가 온전히 고정된 상태

2.4 [4단계] Wwise 프로젝트 설정

언리얼에서 오클루전 값(0~1)을 계산해 넘겨주면, Wwise가 “얼마나 소리를 줄이고 먹먹하게 할지” 결정합니다. Wwise Authoring Tool의 Environmental Curves 탭에서 다음과 같이 설정했습니다.

설정 항목 권장값 설명
Occlusion Volume -15dB ~ -20dB 완전 차단(장애물 뒤) 시 볼륨 감쇠량
Occlusion LPF 30 ~ 50 고음 차단을 통해 먹먹한 느낌을 주는 저주파 필터링 강도
주의: Volume 끝점이 기본값인 -200dB(완전 소거)로 되어 있으면 소리가 완전히 사라지므로, -15dB ~ -20dB 정도로 조절해야 문이나 벽 너머 몬스터의 존재를 오디오 톤으로 감지할 수 있습니다.
그림 3: Wwise의 Environmental Curves 탭에서 Occlusion Volume 및 LPF 관계 곡선을 매핑한 설정 화면

2.5 [5단계] 개별 사운드 설정

설정된 오클루전이 동작하기 위해선 각 사운드 액터나 이벤트의 Positioning 탭에서 Diffraction and Transmission 체크박스를 활성화해야 벽을 통과하는 사운드 회절 및 댐핑이 계산됩니다.

그림 4: Wwise 사운드 에셋의 Positioning 탭에서 Diffraction 및 Transmission 활성화

2.6 [6단계] 디버그 시스템 구축

오클루전이 실제 런타임에 올바른 지점에서 계산되는지 시각적으로 검증하기 위해 디버그 라인 시스템을 구현했습니다. 

// GS_AudioComponentBase.cpp - 콘솔 변수 정의
static TAutoConsoleVariable<int32> CVarShowOcclusionRay(
    TEXT("GS.Audio.ShowOcclusionRay"),
    0,
    TEXT("Show audio occlusion debug rays (0=Off, 1=On)"),
    ECVF_Cheat
);

// 디버그 라인 출력 함수
void UGS_AudioComponentBase::DrawOcclusionDebug(
    UWorld* World, 
    const FVector& SoundLocation, 
    const FVector& ListenerLocation, 
    bool bIsOccluded)
{
    if (CVarShowOcclusionRay.GetValueOnGameThread() == 0) return;
    
    FColor LineColor = bIsOccluded ? FColor::Red : FColor::Green;
    
    DrawDebugLine(
        World,
        SoundLocation,
        ListenerLocation,
        LineColor,
        false,      // 영구 표시 아님
        1.0f,       // 1초간 유지 (깜빡임 방지)
        0,
        2.0f        // 선 두께
    );
}
  • 콘솔 명령어:
    • 활성화: GS.Audio.ShowOcclusionRay 1
    • 비활성화: GS.Audio.ShowOcclusionRay 0
  • 디버그 라인 색상:
    • 초록색: 장애물 없음 (소리 정상 전달)
    • 빨간색: 장애물 감지됨 (Wwise 오클루전 필터 적용 중)
그림 5: 실제 인게임 플레이에서 벽에 의해 차단된 영역에 빨간색 오클루전 디버깅 레이가 맺힌 모습

3. 벽/문 콜리전 요구사항

Wwise 연동 레이트레이스는 소리 위치와 리스너(카메라) 사이에 Line Trace를 수행합니다. 이때 Visibility 채널을 사용하므로, 벽과 문의 콜리전 설정이 중요합니다.

설정 항목 필요 조건
Collision Preset BlockAll 또는 커스텀 프리셋
Visibility Channel Block (차단) 설정 필수
그림 6: 액터의 콜리전 설정 중 Visibility 채널을 Block하도록 지정한 모습

4. 최종 적용 결과

클래스명 오클루전 설정 비고
AGS_Monster 활성화 (0.2초 간격) 모든 몬스터 발소리, 공격음 등에 차폐 계산 적용
AGS_TrapBase 활성화 (0.2초 간격) 트랩 작동음, 톱날 소리 등
AGS_Player (원격) 활성화 (0.2초 간격) 타 플레이어가 내는 발소리 및 스킬음 차폐 적용
AGS_Player (로컬) 비활성화 본인 캐릭터 1인칭 카메라 간의 자가 차폐 오작동 방지
AGS_Door 활성화 (0.2초 간격) 문 여닫힘 상태에 따른 소리 감쇠

최종 효과

  • 벽 뒤의 소리가 물리적 거리에 맞춰 자연스럽게 감쇠됩니다.
  • LPF 먹먹한 효과로 공간감 향상 및 위험 식별력 확보.
  • 디버그 콘솔 라인을 통해 개발/QA 기획 시 실시간 검증이 용이해졌습니다.
  • 간격 체크 주기(0.2초) 조절로 멀티플레이 세션 런타임 성능 부하를 최소화했습니다.

5. 향후 참고 및 체크리스트

  • Wwise 설정 체크리스트:
    • Project Settings → Environmental Curves 탭에서 Volume 감쇠가 -15dB ~ -20dB인지 확인 (완전 음소거 방지).
    • Project Settings → Occlusion LPF 커브 설정 (30 ~ 50).
    • 개별 사운드 → Diffraction and Transmission 체크. Actor-Mixer 단계에서 설정하면 하위 사운드가 상속받음.
  • 언리얼 설정 체크리스트:
    • 벽/문 메시의 Visibility 채널이 Block인지 확인.
  • 디버깅 방법:
    • 콘솔에서 GS.Audio.ShowOcclusionRay 1 입력 후 라인 트레이스 피드백 모니터링 (초록선: 장애물 없음 / 빨간선: 차단됨).
    • Wwise Profiler에서 실시간 오클루전 값 모니터링 가능.

그림 8: 디버그 모드가 켜진 환경에서 여러 오브젝트를 복합 통과하는 차폐 파라미터 레이아웃 최종 확인

본 프로젝트의 오디오 오클루전 시스템은 게임 기획 요구사항 분석에서 출발해 엔진 및 미들웨어 통합, 예외 케이스 처리(로컬 캐릭터 예외 처리 및 리스너 중복 활성화 방지), 그리고 실시간 디버그 라인 설계까지 직접 트러블슈팅하여 일군 결실입니다.
